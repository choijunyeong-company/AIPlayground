# 소크라테스 문답 정리 가이드

## 1. 기본 작성 규칙

어조, 문장 구성, 라인 나누기, 마크업, 코드블럭, 하이라이팅, 출력 형식은 `../create-document-content/SKILL.md`의 규칙을 그대로 따릅니다.
작성을 시작하기 전에 해당 파일을 반드시 읽습니다. 아래 규칙과 충돌하는 경우에만 이 문서의 규칙을 우선합니다.

기본 규칙과 다른 점은 하나입니다.
중주제(`##`)는 분량과 관계없이 항상 사용합니다. 이 문서에서 중주제는 분량을 나누는 용도가 아니라 문답에서 나온 질문을 담는 단위이기 때문입니다.

## 2. 문서 구조

문서는 아래 네 개의 대주제로 구성하며, 순서를 바꾸지 않습니다.

<structure>
# 상황

# 행동

# 결과

# 문답 중 함께 다룬 내용
</structure>

## 3. 중주제 작성 규칙

### 3-1. 중주제는 질문 형태로 작성

각 대주제 아래 중주제는 문답에서 실제로 다룬 질문을 질문 형태 그대로 제목으로 사용합니다.
<good_example>
## 그것이 왜 문제인가
## 이 해결책이 맞는가: 커밋 이력이 다시 쓰인다면
</good_example>
<bad_example>
## 문제점
## 엣지 케이스 4
</bad_example>

### 3-2. 대주제별 중주제 후보

아래 목록은 출발점일 뿐이며, 문답에서 다루지 않은 질문은 만들지 않고 다룬 질문은 목록에 없더라도 추가합니다.

상황
- 어떤 현상이 발생했는가
- 그것이 왜 문제인가: 문제였던 것과 함께, 문제가 아니었던 것도 명시해 해결 범위를 확정합니다.
- 원인은 무엇이었는가: 직접 원인에서 근본 원인까지 한 단계씩 따라갑니다.

행동
- 무엇을 해결해야 했는가: 원인에서 해결 대상을 다시 정의합니다.
- 실제로 수행한 행동: 행동마다 하나의 중주제를 둡니다. 예를 들면 "진행 상태를 어디에 기록했는가"와 같은 형태입니다.
- 이 해결책이 맞는가: 문답에서 점검한 경계 조건마다 `이 해결책이 맞는가: <조건>` 형태로 중주제를 하나씩 둡니다. 처음 대응에 빈틈이 발견되어 수정했다면 처음 대응, 빈틈, 수정한 대응 순서로 서술합니다.
- 대안은 없었는가: 문답에서 언급된 대안과 채택하지 않은 이유를 함께 씁니다.

결과
- 결과는 어떻게 되었는가
- 결과를 측정한 기준은 무엇인가
- 그 기준은 적절한가
- 해결책이 놓친 것은 없는가: 해결책이 내려놓은 것과 그것이 실제로 문제가 되는지에 대한 결론을 씁니다.
- 이 경험에서 얻은 원칙은 무엇인가: 다른 상황에도 적용할 수 있는 형태로 일반화합니다.

문답 중 함께 다룬 내용
- 알고도 받아들인 한계
- 해결책이 동작하기 위한 전제 조건
- 구현 시 참고 사항
- 별도로 관찰한 기록
- 남은 확인 사항
- 다른 영역에서 찾을 수 있는 같은 구조

이 대주제의 중주제는 해당 내용이 문답에 있을 때만 작성합니다.

## 4. 내용 배치 규칙

### 4-1. 문답을 빠짐없이 반영

작성 전에 대화 전체를 처음부터 다시 읽고, 질문과 답변 쌍을 하나씩 중주제에 배정합니다.
어느 중주제에도 자연스럽게 들어가지 않는 문답은 버리지 않고 `문답 중 함께 다룬 내용`에 기록합니다.

### 4-2. 성과 기준은 처음 정의한 문제와 대응

`결과`에서 성과로 내세우는 기준은 `상황`에서 정의한 문제에 대응하는 것만 사용합니다.
처음부터 문제가 아니었던 지표나 부수 효과로 기대한 지표는 성과로 쓰지 않고, `문답 중 함께 다룬 내용`의 관찰 기록으로 분리합니다.
문제가 아니었던 지표를 "측정이 어려웠다"처럼 쓰지 않고, "처음부터 고려 대상이 아니었다"와 같이 실제 판단을 그대로 씁니다.

### 4-3. 사용자의 답을 우선

문답 중 질문자가 제기한 우려라도 사용자가 근거를 들어 해소했다면, 사용자의 결론을 본문의 결론으로 씁니다.
사용자가 답하지 않았거나 결론이 나지 않은 질문은 추측으로 채우지 않고 `남은 확인 사항`에 기록합니다.

### 4-4. 민감한 값 제외

커밋 SHA, 토큰, 내부 식별자 같은 실제 값은 `<SHA>`처럼 자리표시자로 바꿉니다.
외부 업무나 문서를 조회해 인용한 경우 본문 내용만 사용하고, 참조자 목록 같은 개인 정보가 담긴 메타데이터는 포함하지 않습니다.

## 5. 출력

문서의 제목은 작성하지 않습니다.
작성한 문서는 스크래치패드 디렉터리에 `.md` 파일로 저장한 뒤 `pbcopy`로 클립보드에 복사합니다.
응답에는 문서의 중주제 목차와 작성 중 내린 판단만 요약해 전달합니다.
