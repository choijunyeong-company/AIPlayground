---

HEAD 기준 변경사항 전체를 하나의 커밋으로 만드는 스킬입니다. 아래 절차를 순서대로 수행합니다.

## Step 1. 현재 변경 내역 전수 확인

- `git status`로 추적/미추적 파일 전체 목록을 확인합니다.
- `git diff HEAD`로 HEAD 기준 모든 변경된 diff를 확인합니다.
- 필요 시 `git diff HEAD --stat`을 함께 사용해 변경 규모를 파악합니다.

## Step 2. 변경 내역 전체 스테이징 (안전 절차)

- `git add -A`는 비밀파일(`.env`, `*.pem`, `credentials.json`, 토큰 파일 등)을 의도치 않게 포함시킬 위험이 있습니다.
- Step 1에서 파악한 **변경된 파일 목록을 사용자에게 그대로 보여주고**, 시크릿 가능 파일이 섞여 있는지 함께 검토하도록 명시적 동의를 받습니다.
  - `.env`, `.env.*`, `*.key`, `*.pem`, `*.p12`, `id_rsa`, `credentials*`, `secrets*` 등이 포함된 경우 **사용자 확인 없이 절대 커밋하지 않습니다.** 경고 후 처리 방안을 묻습니다.
- 사용자가 명시적으로 "전체 커밋" 진행에 동의하면 그제서야 스테이징합니다.
  - 권장 명령: 파일별 명시적 추가가 가장 안전하지만, 본 스킬의 목적이 "전체 커밋"이므로 사용자 동의 후에는 `git add -A` 사용을 허용합니다.

## Step 3. 작업 의도 파악

- 세션 컨텍스트(이전 대화, 작업 흐름)와 Step 1에서 확인한 diff를 종합하여 이번 변경의 의도를 파악합니다.
- 다음 중 하나에 해당하면 **임의로 추정하지 말고 사용자에게 작업 의도 프롬프트를 요청한 뒤 입력을 대기**합니다.
  - 의도가 불명확함
  - 여러 작업(기능 추가/리팩토링/버그 픽스 등)이 얽혀 하나로 특정하기 어려움
  - 세션 컨텍스트가 부족하여 변경의 "왜"를 단정할 수 없음
- 사용자가 의도를 제공하면 그 답변을 Step 5의 커밋 메시지 본문 근거로 사용합니다.

## Step 4. 커밋 템플릿 확인

- 현재 작업 디렉터리 이름을 구합니다. 예: `basename "$PWD"` 결과 `MyRepo` → 템플릿 경로는 `~/.commitTemplates/MyRepo.md`.
- `~/.commitTemplates/{cwd이름}.md` 존재 여부를 확인합니다.
  - **존재하는 경우**: Read 툴로 해당 파일을 읽어 커밋 형식(타이틀 규칙, 본문 섹션 구성 등)을 파악합니다.
  - **존재하지 않는 경우**: 본 스킬 실행을 중단하지 말고, 먼저 `init-commit-template` 스킬을 Skill 툴로 호출하여 템플릿을 생성합니다.
    - 호출 방법: Skill 툴을 사용하며 `skill` 파라미터에 `init-commit-template`을 지정합니다.
    - 예: Skill(skill="init-commit-template")
    - 템플릿 생성 완료 후 본 스킬의 Step 4로 복귀하여 새로 만들어진 템플릿 파일을 읽습니다.

## Step 5. 커밋 메시지 작성 및 커밋 생성

- Step 4에서 얻은 템플릿 형식에 맞춰 **타이틀 + 본문**으로 구성된 커밋 메시지를 작성합니다.
- 타이틀은 변경의 핵심을 한 줄로, 본문은 Step 3에서 확정된 작업 의도 및 변경 요지를 정리합니다.
- `git commit -m "..."` 또는 HEREDOC 방식으로 커밋을 생성합니다.
- **사용자 환경의 hook은 절대 우회하지 않습니다.**
  - `--no-verify`, `--no-gpg-sign`, `-c commit.gpgsign=false` 등 hook/서명 우회 옵션 사용 **금지**.
  - hook이 실패하면 원인을 진단하고 수정한 뒤 **새 커밋**으로 다시 시도합니다(amend가 아닌 신규 커밋).

## Step 6. 결과 보고

- `git status`로 커밋이 정상적으로 생성되어 워킹트리가 깨끗해졌는지 확인합니다.
- `git log -1 --stat`으로 방금 생성된 커밋 정보(해시, 타이틀, 변경 파일 수)를 확인합니다.
- 사용자에게 다음을 보고합니다.
  - 생성된 커밋 해시 및 타이틀
  - 포함된 파일 수
  - 후속 작업(예: 푸쉬 여부)은 별도 지시가 없으면 수행하지 않음을 명시

## 안전 수칙 요약

- 시크릿 가능 파일(`.env`, 키/인증서 등)은 **사용자 확인 없이 커밋 금지**.
- `--no-verify` 등 hook 우회 옵션 **사용 금지**.
- 의도가 불명확하면 추정 금지, **사용자에게 질문**.
- 커밋이 실패한 경우 `--amend`가 아닌 **새 커밋**으로 재시도.
