# init-commit-template

## 개요

현재 작업 디렉터리의 git 커밋 이력을 분석하여 해당 프로젝트의 커밋 컨벤션(타이틀 접두사, 어조, 언어, 본문 스타일 등)을 추출하고, 그 결과를 `~/.agent-memory/commitTemplates/{cwd이름}.md` 경로의 마크다운 템플릿 파일로 저장합니다. 이후 `whole-commit`, `separate-commit` 등 다른 커밋 관련 스킬이 템플릿을 참조하여 일관된 스타일의 커밋 메시지를 생성할 수 있도록 합니다.

## 절차

### Step 1: 템플릿 저장 디렉터리 확인 및 생성

`~/.agent-memory/commitTemplates` 디렉터리의 존재 여부를 확인하고, 없으면 생성합니다.

```bash
mkdir -p ~/.agent-memory/commitTemplates
```

### Step 2: 현재 작업 디렉터리 이름 도출

git 저장소 루트의 디렉터리명을 추출합니다. git 저장소가 아니라면 현재 작업 디렉터리명을 사용합니다.

```bash
basename "$(git rev-parse --show-toplevel 2>/dev/null || pwd)"
```

이 결과를 `{cwd이름}` 변수로 사용합니다.

### Step 3: 최근 커밋 충분량 조회

분석 신뢰도를 확보하기 위해 최소 30개 이상(권장 50개)의 최근 커밋을 조회합니다. 타이틀과 본문을 모두 가져옵니다.

```bash
git log -n 50 --pretty=format:"%s%n%b%n---"
```

만약 커밋 수가 30개 미만이면 가능한 모든 커밋을 조회하고, 0건이라면 사용자에게 분석 불가 사실을 알리고 중단합니다.

### Step 4: 커밋 스타일 철저 분석

조회한 커밋들을 다음 항목에 따라 철저히 분석합니다.

- **접두사 패턴**: `[Feat]`, `Feat,`, `feat:`, `fix:`, `chore:` 등 실제 사용되는 형태를 그대로 파악합니다. (대소문자, 구분자, 괄호 사용 여부 포함)
- **어조**: 명령형(`add`, `fix`), 과거형(`added`, `fixed`), 한국어 `~함`/`~추가` 종결 등 어떤 어조가 주류인지 식별합니다.
- **언어**: 타이틀/본문이 한글인지 영문인지, 혼용 여부도 확인합니다.
- **메시지 본문 유무**: 본문을 거의 사용하지 않는지, 자주 사용하는지 파악합니다. 본문이 있다면 들여쓰기 / 불릿(`-`, `*`, `1.`) 스타일을 확인합니다.
- **줄바꿈 및 길이**: 타이틀 최대 길이, 본문 줄당 길이, 타이틀과 본문 사이 빈 줄 유무 등 일반 규약을 정리합니다.
- **기타 패턴**: 이슈 번호 표기(`#123`), 스코프(`feat(scope):`), 머지 커밋 패턴 등 특이사항을 식별합니다.

### Step 5: 분석 결과를 마크다운 문서로 작성

추출한 컨벤션을 사람이 읽기 쉬운 마크다운으로 정리합니다. 다음과 같은 구조를 권장하되 자유롭게 구사할 수 있습니다.

```md
# {cwd이름} 커밋 템플릿

## 타이틀 형식
- 접두사: `Feat,` / `Fix,` / `Refactor,` ...
- 언어: 한글
- 어조: 명사형 종결 ("~ 추가", "~ 수정")
- 예시:
  - `Feat, 사용자 로그인 기능 추가`
  - `Fix, 토큰 만료 처리 버그 수정`

## 메시지(본문) 형식
- 본문 사용 빈도: 자주 사용 / 거의 사용 안 함
- 들여쓰기: 없음 / 2 spaces
- 불릿: `-`
- 예시:
  ...

## 기타 규약
- 타이틀 최대 길이: 약 50자
- 본문은 타이틀과 한 줄 띄우고 작성
- 이슈 번호: `(#123)` 형태로 타이틀 끝에 표기
```

분석된 실제 패턴에 맞추어 항목을 가감할 수 있습니다.

### Step 6: 템플릿 파일 저장

`Write` 툴을 사용하여 `~/.agent-memory/commitTemplates/{cwd이름}.md` 경로로 저장합니다.

- **이미 동일 파일이 존재할 경우**: 사용자에게 덮어쓸지 여부를 명시적으로 확인합니다. 사용자가 거부하면 저장하지 않고 중단하거나, 다른 파일명을 제안합니다.

```bash
# 존재 여부 확인 예
[ -f "$HOME/.agent-memory/commitTemplates/{cwd이름}.md" ] && echo "exists" || echo "new"
```

### Step 7: 사용자에게 결과 보고

저장이 완료되면 다음을 사용자에게 보고합니다.

- 저장된 파일의 절대 경로 (`~/.agent-memory/commitTemplates/{cwd이름}.md`)
- 분석된 커밋 수
- 식별된 주요 컨벤션 요약 (접두사, 언어, 어조 등 한두 줄)

## 주의 사항

- 본 스킬은 **분석과 저장**만을 담당합니다. 실제 커밋 메시지 생성/적용은 `whole-commit`, `separate-commit` 등 다른 스킬에서 이 템플릿을 참조하여 수행합니다.
- git 저장소가 아닌 디렉터리에서는 git log 조회가 실패하므로, 사용자에게 분석 불가 사실을 알리고 중단합니다.
- 머지 커밋(`Merge branch ...`)은 분석 노이즈가 될 수 있으므로 가중치를 낮추거나 별도로 표기합니다.
- 템플릿이 이미 존재하더라도 사용자 동의 없이 덮어쓰지 않습니다.
