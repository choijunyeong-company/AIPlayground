# 문서작성 가이드

## 1. 과도한 마크업 사용 금지

### 1-1. 문장 작성

볼드, 이탈릭, 하이라이팅 등 텍스트에 적용 가능한 마크업 문법 사용을 최소화합니다. 최대한 자세하게 문장을 구성합니다.
문장은 주장을 서술하고 이를 뒷받침하는 근거를 이어서 서술하는 방식을 지향합니다.
<good_example>
임베딩은 AI가 이미지를 이해하는데 필수적입니다. 왜냐하면 프로그램은 오직 수치만 읽을 수 있기 때문입니다.
</good_example>
<bad_example>
임베딩은 AI가 이미지를 이해하는데 가장 핵심적입니다.
</bad_example>

### 1-2. 인용문 사용

현재 설명중인 내용과 다소 무관하지만, 이후 작업 진행 및 개발자의 관점에서 중요한 내용이라고 판단되는 내용인 경우 인용문을 통해서 내용을 작성합니다.

### 1-3. 표 사용

표는 반드시 비교군이 있는 경우에만 사용합니다.
텍스트 문장으로 비교군들의 차이를 500자 이하로 설명할 수 있다면 표를 생성하지 않습니다.

## 2. 문단 단위 설명

주제에 따라 각 섹션(문단)으로 문서 구조를 분리하여 설명합니다.
섹션 마크업(#)이 등장하면 반드시 공백 라인을 추가한 이후에 컨텐츠를 작성합니다.
대주제에 담아내는 설명 내용이 1,000자 이상으로 비대해지는 경우에만 중주제 섹션을 사용하여 분할합니다.
문서는 기본적으로 다음과 같은 구조를 가집니다.
<good_example>
# 개요

안녕하세요.

# 대주제1

안녕하세요.

## 중주제

안녕하세요.

# 대주제2
</good_example>
<bad_example>
## 개요
안녕하세요.
#### **주제1**
안녕하세요.
#### **주제2**
안녕하세요.
</bad_example>

## 3. 라인 나누기

한 라인에 두 문장을 작성했다면 다음 문장은 반드시 라인을 나누어 새 라인에 작성합니다.
연속되는 라인이 4개 이상 이어지는 경우, 아무것도 작성되지 않은 공백 라인을 하나 삽입하여 가독성을 확보합니다.

## 4. 코드블럭 사용

메서드, 변수, 특정 타입이 문서에 포함되는 경우 반드시 인라인 코드블럭 스타일을 사용합니다.
<good_example>
`animation(body:)` 수정자를 사용하면 애니메이션이 적용될 스코프를 명시적으로 지정할 수 있습니다.
</good_example>

## 5. 출력 형식

출력 결과는 바로 복사 붙여넣기 가능한 문서의 컨텐츠입니다.
문서의 제목은 작성하지 말고 내용만 출력해주세요.
출력과 동시에 클립보드에 출력 결과를 복사해주세요.
